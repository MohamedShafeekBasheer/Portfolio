Most "I've lost my file" problems in SharePoint can be fixed in under a minute, without raising a ticket. There are two situations, and a built-in fix for each.

## "I deleted the file"

Deleted files go to the site's **Recycle bin**, not straight into thin air.

1. Go to the SharePoint site where the file was.
2. Open the **Recycle bin**. It's in the left-hand menu, or under **Site contents** at the top right.
3. Tick the file and select **Restore**.

The file goes back to the same library and folder it was deleted from, with its version history.

**Not there?** If someone emptied the recycle bin, the file moves to a **second-stage recycle bin**, which a site owner or SharePoint admin can see at the bottom of the Recycle bin page. Deleted items are kept for **93 days** in total across both stages, so don't leave it too long.

## "I saved over it" or "someone changed it"

This is what **version history** is for. SharePoint keeps earlier versions of a file every time it's saved, and document libraries have it switched on by default.

1. In the document library, select the file (don't open it).
2. Select **⋯** (more options) and choose **Version history**.
3. Find the version from before the change: you can see who saved each one and when.
4. Open it to check, then choose **Restore**.

Restoring doesn't delete the newer versions. It saves the old one as the newest version, so you can always go back again.

## Two habits that save trouble later

- **Use the library, not email attachments.** A file in SharePoint has version history and a recycle bin. A copy in someone's inbox has neither.
- **Don't download, edit, and re-upload.** Open the file from SharePoint and edit it in place, so every change is kept as a version.

The same two features work in **OneDrive** for your personal files: there's a Recycle bin in the left-hand menu, and Version history on every file.
